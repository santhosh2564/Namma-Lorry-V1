## 1. i18n

**Checked**
- Every string in `app/` and `src/`: JSX text, text props (`label`, `title`, `placeholder`, `accessibilityLabel`/`Hint`, `message`, `error`, …) and model files that build text (status chips, metric labels, timeline, battery steps, months, age text, tracking errors, the foreground-service notification).
- Strings read while a module loads. These stay in the language that was active at that moment and never switch.

**Changed**
- **Catalogs**
  - `src/i18n/en.ts` is replaced by `en.json`, the source of truth.
  - `ta/kn/hi.json` are generated by `npm run i18n:sync` (`scripts/i18n-sync.js`). Each new key is added as `"TODO: <English>"` and existing translations are kept.
  - `npm run i18n:check` fails CI if the files drift apart.
- **Runtime:** `src/i18n/i18n.ts` holds i18next 26.4.2. Resources are bundled and init is synchronous.
  - Interpolation uses `{{name}}`.
  - Plurals use `_one`/`_other` keys.
  - Values starting with `TODO` are dropped at load time, so untranslated text falls back to English instead of showing "TODO". A list (month names, battery steps) is only used when every item in it is translated.
- **Typed API:** `src/i18n/index.ts` exports `t`, which has the same shape as the old `en` object.
  - Every string leaf is a getter, so it always returns the current language.
  - Parameterised entries (plurals, distances, reason codes) are typed functions.
  - `pick(map, code, fallback)` looks up dynamic codes.
  - `useLanguage()` re-renders a component on a language change, and every route calls it. Console column headers are getters.
- **Per-user language**
  - Migration **0005** adds `set_preferred_language(p_language)`, a SECURITY DEFINER function that changes only the caller's own row. Drivers still have no UPDATE policy on `profiles` (docs/09 §4).
  - It also adds a CHECK constraint (`en|ta|kn|hi`, not null).
  - `src/features/settings/language.ts` saves the choice on the phone (SecureStore on native, localStorage on web) and on the profile.
  - A choice made while signed out is pushed to the profile at the next sign-in. Otherwise the profile's language wins (`LanguageSync` in the root layout).
  - The splash stays until the saved language is applied.
- **UI:** a shared `LanguageSheet` on S2 (previously it only said "coming soon") and on D8.
  - Each language is listed by its own name.
  - Languages that are still partly English say so.
  - If the save fails, the choice is kept on this phone and a warning is shown.
- **Not translated on purpose:**
  - language names (a driver must recognise their own)
  - phone brand names on D2
  - SI unit symbols (`km`, `m`, `min`, `h`, `s`) in number formatters
  - admin-entered data (addresses, names, notes)

**Checks**
- `src/i18n/hardcoded.test.ts` has two AST scans over every `.tsx`/`.ts` in `app/` and `src/` (except `app/dev`).
  - It fails on any literal UI text, including text inside `?:`, `??`, `+` and template literals in text props.
  - It fails on any string read from `t` at module load.
- `src/i18n/i18n.test.ts` checks:
  - key parity for ta/kn/hi
  - identical `{{placeholders}}`
  - TODO fallback
  - live switching
  - plurals
  - that every error code has a message (see §2)
- RNTL D8: picking தமிழ் calls `set_preferred_language('ta')` and updates the row.
- pgTAP `language.test.sql` (8 tests):
  - a driver can set their own language only
  - an unsupported value is refused
  - a direct UPDATE changes nothing
  - the CHECK constraint holds
  - anon is refused

**Found and fixed along the way**
- D6's header texts were built at module load and would never have switched language. They now build at render.
- D8, C6 metrics and timeline, C5 dates and D7 month names had their own English month and label tables. They now come from the catalog.

## 2. Error handling

**Checked:** every data screen for loading, error and empty states, and every error code the backend can return.

**Changed**
- **Global error boundary:** `src/components/ErrorBoundary.tsx`.
  - `AppErrorBoundary` wraps the root providers.
  - The root layout exports `ErrorBoundary = RouteErrorBoundary`, which Expo Router uses for any route.
  - Both report to Sentry, show a friendly screen with **Try again** (and **Go to start** at route level), and never show the raw error text.
  - The background task and the SQLite queue live outside React, so recording continues.
- **One error mapper:** `src/lib/errorMessage.ts`. `errorInfo(e)` turns any error into a stable code:
  - RPC `raise exception` codes, including `OUTSIDE_PICKUP:<m>` with its distance
  - Edge Function `{ error: CODE }`
  - Postgres SQLSTATEs (42501, 23505, 23514, …)
  - PostgREST JWT errors
  - network failures

  `errorMessage(e, overrides?)` returns the text for that code from `en.json` `errors`, and a screen can supply its own text per code.
- **`ErrorBanner`** (`src/components/ui`): the message plus **Try again**, which refetches. Added to:
  - screens that had no error state: D8 profile/stats, D6 when the trip can't be loaded, C6 points and timeline, C4 driver/vehicle lists
  - screens that had a message but no retry: C1, C7, D4, C4, C6
  - D3, D7 and C2/C5/C8/C9 already had error states with pull-to-refresh or DataTable retry, and are unchanged.
- **Tracking errors:** `tripErrorText` in `src/tracking/errors.ts` now uses the catalog.
- **Query and mutation errors** are reported to Sentry globally from the React Query caches. Expected conditions are not reported: `NETWORK`, `TIMEOUT`, session expiry, `RATE_LIMITED`.

**Checks**
- `i18n.test.ts` reads every `raise exception 'CODE'` in `supabase/migrations/*.sql` and every `HttpError(status, 'CODE')` / `error(status, 'CODE')` in `supabase/functions`, and fails if any code has no text in `en.json` `errors`.
  - This check found 5 `MAPPLS_*` codes from `mappls-proxy` with no message. They now have one.
- `errorMessage.test.ts`: 13 tests.
- `ErrorBoundary.test.tsx`: the crash screen shows, the error is reported once, the raw text is hidden, and retry recovers.
- RNTL D8: an offline error shows "You're offline…"; Try again recovers.

## 3. Sentry (ND-11)

**Changed**
- **`src/lib/sentry.ts`:** one module for native and web (`@sentry/react-native` 7.11.0, the version Expo SDK 57 expects).
  - Release `namma-lorry@<nativeApplicationVersion>+<nativeBuildVersion>`, with `dist` set to the build number. On web the version comes from `app.config.ts` and `dist` is `web`.
  - `environment` comes from `EXPO_PUBLIC_APP_ENV`, and there is a `platform` tag.
  - Initialised once at module load in `app/_layout.tsx`, which is wrapped with `Sentry.wrap`.
  - The user is attached by **UUID only**, following auth changes.
- **`src/lib/scrub.ts`** runs on every event (`beforeSend`) and breadcrumb (`beforeBreadcrumb`).
  - It drops keys such as `phone`, `lat`, `lng`, `p_lat`, `coords`, `path`, `points`, `token`, `otp`, `email`, `ip_address`.
  - It removes Indian mobile numbers (with or without +91, spaces or dashes) and other `+`-prefixed numbers from strings.
  - It removes coordinate pairs, `lat=`/`lng=`/`phone=` query parameters, lone decimals with 4 or more places, and numbers that look like coordinates.
  - It keeps only `user.id` and only the request `url`/`method`.
- **Settings:** `sendDefaultPii: false`, `attachScreenshot: false`, `attachViewHierarchy: false` (view text can contain names and numbers), `tracesSampleRate: 0` (errors only).
- **Config:** `EXPO_PUBLIC_SENTRY_DSN` (optional, zod-validated) is in `config.ts` and `.env.example`. `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT` are build-time only.
  - `app.config.ts` adds the `@sentry/react-native/expo` plugin only when org and project are set, for source-map upload on EAS.
  - `metro.config.js` uses `getSentryExpoConfig` so bundles carry debug IDs.

**Checks**
- `scrub.test.ts`: 12 cases, including ids, versions and timestamps that must be kept.
- `sentry.test.ts`:
  - with no DSN nothing is initialised or sent
  - with a DSN: the release and dist, no default PII, the scrubbers are wired, and the user is id-only

**Needs a human:** create the Sentry project, set `EXPO_PUBLIC_SENTRY_DSN` per EAS profile and web deploy, and store `SENTRY_AUTH_TOKEN` as an EAS secret (M12c).

## 5. Performance

**Changed**
- **Map layers are memoised** (`MapView.web.tsx`).
  - Circles, polylines and markers each have their own layer list and change key, and redraw independently.
  - A moving truck (C1, D5) or the C6 replay cursor, which ticks every 100 ms, now redraws only the markers, not the route or the geofences.
  - The polyline key is a numeric hash (`pathsKey`) instead of `JSON.stringify` over thousands of points on every render.
  - Map creation moved below the draw functions, and the handler ref is updated in a layout effect. This clears the React Compiler lint errors that the old structure only avoided by bailing out.
- **Display simplification** (`src/lib/geo.ts`).
  - `douglasPeucker(path, toleranceM)` is iterative and works on a local metric projection computed once per path.
  - `simplifyForDisplay(path, max = 1000)` raises the tolerance (5 m, 10 m, 20 m…) until the line has at most 1,000 points. It always keeps both ends, and pre-thins paths over 5,000 points.
  - It is applied to every polyline the web map draws. Raw points still feed replay, local km and review.
  - A 20,000-point zigzag is simplified in about 15 ms in Jest; the first version was O(n²) with a trig call per point and timed out.
- **Background task:** no network I/O.
  - `task.ts` imported `getTrackingDb` from `runtime.ts`, which imports Supabase and the uploader. Nothing on the network was called, but the task's module graph could reach it.
  - The DB opener moved to `src/tracking/trackingDb.ts`. The task now reaches only `taskHandler`, `queue`, `db`, `mapping`, `config` (and i18n for the notification text).

**Checks**
- `geo.test.ts`: Douglas–Peucker on a straight line and a corner, the cap, both ends kept, short paths left alone.
- `__tests__/taskIsolation.test.ts`:
  - walks the task's import graph and fails if it reaches `lib/supabase`, `uploader`, `runtime` or `lib/functions`, any package outside a local-only allowlist, or any `fetch(`/`XMLHttpRequest`/`WebSocket`
  - runs a real batch through `handleLocationUpdate` with `fetch` stubbed, and asserts two points are queued and `fetch` is never called
